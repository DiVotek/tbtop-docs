# tbtop-docs

Fumadocs site for `tbtop/admin` (repo `DiVotek/tbtop`, public), describing the
latest patch of its current 0.x line. Hosted on Cloudflare Workers as static
assets — a React Router SPA with `ssr:false`, fully prerendered at build time.

## Pinned tag

`PINNED_TAG` in `app/lib/shared.ts` is the only place the described release
is pinned. To bump it: update `PINNED_TAG`, run `npm run sync:api`, review
the diff in `content/docs/(admin)/api/`, commit both together.

Install commands write the version as `__PINNED_VERSION__`; the remark plugin
in `app/lib/remark-pinned-version.ts` fills it from `PINNED_TAG` at build.

## Generated content

`content/docs/(admin)/api/*.mdx` and its `meta.json` are generated by
`scripts/sync-api.ts` (`npm run sync:api`) from `docs/ai/api/*.md` in
`DiVotek/tbtop` at `PINNED_TAG`. Never hand-edit them — edit the script and
rerun it. The CMS reference pages (`content/docs/cms/reference/`) follow the
same rule once their sync lands. Everything else under `content/docs/` is
hand-written.

## Gates

```bash
npm run lint
npm run format:check
npm run types:check
npm run build
```

No persistent test suite; the build's prerender step is the correctness
check for MDX and routes.

## Deploy

A merge to `main` deploys: `.github/workflows/ci.yml` runs the gates, then
`wrangler deploy` with the `CLOUDFLARE_API_TOKEN` repo secret. Direct pushes to
`main` are blocked by a ruleset; every change lands through a PR. Manual
fallback: `CLOUDFLARE_ACCOUNT_ID=9fc01736a7873ba44582cf173fc5a157 npx wrangler deploy` — the
account that holds the tbtop.dev zone. `wrangler.jsonc` routes docs.tbtop.dev as a
custom domain: Cloudflare creates its DNS record and certificate on deploy, so
no record for that host may exist in the zone beforehand.

## Sections

`content/docs` has two root folders, shown as tabs above the sidebar:
`(admin)` for tbtop/admin (the parentheses keep its pages at `/docs/...`) and
`cms` for tbtop/cms at `/docs/cms/...`.

The CMS ships for Laravel (`tbtop/cms`) and Node (`@tbtop/cms`) under one
version, `CMS_TAG` in `app/lib/shared.ts`. Concepts and guides are one page
per topic with code in `<StackTabs>` (Laravel / Node, one persisted choice
for the whole site); install, reference and upgrading are split per stack.
Every Node-only page carries `<NodeAlpha />` while the Node package is in alpha; a
feature only one stack has gets `<StackOnly stack="…" />`. Reference pages
are synced from the packages, descriptive pages are written here.

Both CMS packages and the tbtop-cms repo are public, so their host-facing
API (install, config, commands, bindings, extension points) belongs here.
Package internals that a host never touches do not.

## Anonymise production examples

An example drawn from a private production project is rewritten generic
before it lands here: no project names, domains, or client code verbatim.
